## Q3 Native PDF APIs
1. Claude API PDF limits: max request 32 MB; max 600 pages per request, but 100 when the request's context window is under 1M tokens; standard PDF only (no password/encryption). Dense PDFs can fill context before the page limit. | https://platform.claude.com/docs/en/build-with-claude/pdf-support | Anthropic | undated (live docs) | 2026-10-28 | high | limit
2. Claude PDF token cost: each page is converted to an image AND its extracted text is supplied. Text is typically 1,500-3,000 tokens/page; image tokens are billed on top at normal image rates; no extra PDF fee. Page example: about 1,000 tokens for a 3-page text-only PDF vs about 7,000 for a 3-page PDF processed as text+image. | same | Anthropic | undated | 2026-10-28 | high | pricing
3. Claude citations on PDFs: PDF text is extracted and chunked into sentences; citations return page numbers (1-indexed, exclusive end page; page_location type) plus cited_text. cited_text does not count toward output tokens. Image citations unsupported, so scanned PDFs are not citable. All active models support citations. PDF citations are page-level, not finer-grained. | https://platform.claude.com/docs/en/build-with-claude/citations | Anthropic | undated | 2026-10-28 | high | pattern/limit
4. Claude docs advise using logical page numbers (from the PDF viewer) in prompts, placing PDFs before text, and splitting large PDFs. | pdf-support page (above) | Anthropic | undated | 2026-10-28 | high | pattern
5. Gemini API: PDFs up to 50 MB or 1,000 pages (inline and Files API); 258 tokens per page; native-PDF text tokens are not billed for Gemini 3 models, page images counted under IMAGE modality. Page-level citation support is not addressed on that page. | https://ai.google.dev/gemini-api/docs/document-processing | Google | undated | 2026-10-28 | medium (summarised by fetch tool; the not-billed claim is surprising, verify) | limit/pricing
6. OpenAI PDF input: files under 50 MB, 50 MB combined per request; no page limit stated. Vision models get extracted text plus page images; both count as context. `detail` (low/high/auto) controls image processing only; auto = high for GPT-5.6 and later, low for earlier. No per-page price given. No native page-citation feature mentioned. | https://developers.openai.com/api/docs/guides/pdf-files | OpenAI | undated | 2026-10-28 | medium-high | limit/pricing
7. Viability: Claude native PDF + citations gives page-numbered citations with no own extraction code; cost is about 1.5-3k text tokens/page plus image tokens. This is my inference from items 1-3, not a sourced benchmark. Citing images/scans not supported. | inference | - | - | 2026-10-28 | medium | pattern

## Q2 Context windows and prices
8. Claude Fable 5.1, Opus 5.5, Sonnet 5.5, Haiku 5.5 all have 1M-token context, 128K max output. Prices per MTok in/out: Fable 5.1 $10/$50; Opus 5.5 $4/$20; Sonnet 5.5 $2/$10; Haiku 5.5 from $0.10/$0.50. Batch API 50% off. | https://platform.claude.com/docs/en/models/overview | Anthropic | undated | 2026-10-28 | high | limit/pricing
9. Official conversion: 1M tokens is about 555k words on the current tokenizer (older models about 750k words); 200k tokens is about 150k words. At ~500 words/page that is ~1,100 pages in 1M (unsourced page size, my arithmetic). Claude's own PDF figure of 1.5-3k tokens/page (text only) implies about 330-650 pages per 1M. | same | Anthropic | undated | 2026-10-28 | high (conversion) / medium (page arithmetic) | limit
10. Consequence: a 100-300 page lecture PDF fits in one 1M-context call, so map-reduce is not needed for v1 on these models; chunking is then for output quality and cost, not capacity. Inference only. | inference | - | - | 2026-10-28 | medium | pattern
